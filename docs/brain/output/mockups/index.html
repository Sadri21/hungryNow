Arrive. Find. Eat.

01–06 / The main flow
01Launch

Launch matches the welcome ground and restaurant-band silhouette; no artificial delay or branding animation.

02Welcome

Restaurant frontage and direct copy introduce the one-tap promise. Continue opens the simulated permission prompt.

03Location permission

Illustrative system alert, not a replacement for native iOS permission UI. Allow and deny branches are clickable.

04Home

The plate becomes a clock: hunger, food, and now in one motif. One primary action, no directory or filters.

05Finding a restaurant

Kitchen-ticket composition; indeterminate clock, honest search copy, and Cancel. Auto-advances only in the interactive demo.

06Your restaurant

Existing restaurant photo and illustrative data. No verified walking time, opening status, or live location. Directions is a demo handoff.

When plans change.

07–09 / Recovery states
07Location off

Clear steps and a single recovery action. Settings is simulated; this prototype never changes device permissions.

08Nothing nearby

A searched radius, a plain explanation, and a retry using a new location in the native implementation.

09Connection problem

Offline and service-unavailable variants have different explanations. Retry is simulated; daily caps are a separate product decision.
